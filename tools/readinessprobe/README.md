# Go readiness baseline probe

`go run ./tools/readinessprobe` reproduces the remaining synthetic observation recorded in `docs/go-readiness-review.md` for R7 process-tree cleanup in the legacy `internal/process` path; the newer launcher-owned job path has separate cancellation regressions. R14 constructor and protected-port validation are covered by permanent regressions in `internal/browser`, `internal/portguard`, `internal/dockerproxy`, `internal/browsernet`, and `internal/service`. R1 is covered by permanent Git path/repository regressions in `internal/work/workspace/git` and `internal/work/workspace`; R3 is covered by strict configuration regressions in `internal/config`; R4 is covered by permanent managed-credential regressions in `internal/secret`, `internal/service`, and `internal/devtools`; R5 is covered by permanent repository-execution regressions in `internal/work/workspace/git`; R8/R9 are covered by permanent regressions in `internal/toolchain/install_test.go` and `internal/toolchain/archive_safety_test.go`; R11 is covered by strict MCP/RPC regressions in `internal/mcpserver`, `internal/rpc`, and `internal/service`.

The command is deliberately **non-gating**. Exit status zero means every isolated observation completed; it does not mean the product is correct and it does not assert that the current broken behavior should remain. The JSON booleans are expected to change as fixes land. Each scenario must be converted into a positive regression assertion in the work item that fixes the corresponding defect, after which the redundant baseline observation can be removed.

The probe now uses only a short-lived synthetic child-process scenario. It does not read the repository index being worked on, Loki runtime sockets, deployed credentials, or host deployment state. The detached-child scenario explicitly kills its synthetic child after observing whether timeout cleanup owned it.
